## 模型与色卡格式

| 格式 | 用途 |
| --- | --- |
| `.cbmodel` | CubeBricks 的完整工程封存。保存模型、贴图与可选的操作历史；导出时可选择只保留当前完整状态。 |
| `.bbmodel` | 与 Blockbench 交换模型。Shape 和修改器在导出时展开为兼容的 Cube／组；原本的程序化参数不会以原生 Shape 形式留在 `.bbmodel`。 |
| `.json` | 仅支持模型原生格式：Java 方块／物品模型和基岩 geometry。按格式处理骨骼、坐标、旋转和 UV，导出前先保存外部贴图。 |
| `.java` | 模组实体的 Mojang 映射模型层；内置完整性校验，仅允许原样导回本软件生成的文件。 |
| `.png` / `.png.mcmeta` | 可独立保存的完整合成贴图，动画使用纵向帧条与配套配置。 |
| `.cbtextures.json` | 原生模型的贴图路径／材质配套索引，使用相对路径；不是通用模型格式，不要单独作为模型打开。 |
| `.cbcmap` | 单张色卡的便携式 JSON，包含颜色、渐变分段和色彩空间曲线，不包含本地名称或 ID。 |
| `.cbmodel` 内的色卡 | 保存项目内色卡；导出时还会附上图层引用的全局色卡，导入后作为该项目的本地色卡使用。 |

## 建模格式边界

原生 JSON 的坐标和字段遵循 [Minecraft Java 1.21.11 多轴旋转说明](https://www.minecraft.net/en-us/article/minecraft-java-edition-1-21-11) 及 [基岩几何文档](https://learn.microsoft.com/en-us/minecraft/creator/reference/content/visualreference/geometry.v1.19.30)。Java 不支持的组层级会合成为元素姿态；版本无法表达的旋转会明确报告失败。模组实体没有 JSON 选项，Java 输出为模型层，不包含游戏注册和动画代码。

`.bbmodel` 中的平铺会转换为普通 UV，手翻书保存为内嵌纵向 PNG 帧条及 Blockbench 动画字段。单贴图格式自动合并贴图，使用最小公倍数帧数与平均 FPS、关闭帧渐变；多贴图格式分别保留。Java 的 `.mcmeta` 时间按游戏整数 tick 表示，因此导出兼容时间会四舍五入且至少为 1 tick，精确 FPS 仍写入贴图字段。参数约定参考 [Blockbench 贴图实现](https://github.com/JannisX11/blockbench/blob/master/js/texturing/textures.js)。烘焙不会改写原工程，平铺区域可重叠引用；超过 16384px 单边或 64M 像素的结果会报告失败，不会偷偷截短序列或缩小贴图。

`.bbmodel` 中的平铺会转换为普通 UV，手翻书保存为内嵌纵向 PNG 帧条及 Blockbench 动画字段。单贴图格式自动合并贴图，使用最小公倍数帧数与平均 FPS、关闭帧渐变；多贴图格式分别保留。Java 的 `.mcmeta` 时间按游戏整数 tick 表示，因此导出兼容时间会四舍五入且至少为 1 tick，精确 FPS 仍写入贴图字段。参数约定参考 [Blockbench 贴图实现](https://github.com/JannisX11/blockbench/blob/master/js/texturing/textures.js)。烘焙不会改写原工程，平铺区域可重叠引用；超过 16384px 单边或 64M 像素的结果会报告失败，不会偷偷截短序列或缩小贴图。

Java 方块／物品项目强制背面剔除和逐面 UV。版本选项分别为 1.9–1.21.5（单轴旋转、22.5° 倍数且限制在 ±45°）、1.21.6–1.21.10（单轴旋转、角度不限）及 1.21.11+（多轴与角度不限）。元素原始 `from/to` 坐标限于各轴 −16～32；旋转后的视觉包围盒不用于替代这个检查。视图参考地网格相对建模原点偏移 +8、0、+8，红蓝轴仍从原点出发。

基岩版方块按实际模型边界检查 30px 尺寸，而非给每个 Cube 固定套上同一个框：范围参考框会随当前模型动态移动，且模型须保留与中心基础范围的有效交叠。两种格式的范围框都是十二条边，采用与地网格主参考线相同的颜色及遮挡方式；它只是视图提示，不是模型几何。若一次编辑进一步增加越界程度，该操作会被拒绝。

新版 `.cbmodel` 封存会把操作 JSON 整合为 Brotli 压缩数据块，按内容去重图片数据并验证解压后的文件；旧 ZIP 版本仍可读取。桌面工作目录另外保存项目范围的操作序列和元素历史；默认最多保留 200 个历史操作，可按项目单独设置。导出时不保留历史不会清空本地工作日志。

顶部「保存」只确认并保留当前展开式工作目录，之后关闭窗口无需再选择是否保留这个项目；需要给别人传文件或额外备份时，请使用「导出」生成 `.cbmodel` 或 `.bbmodel`。保存工作目录不等同于生成独立模型文件。

保留状态独立写入项目目录的 `workspace_state`，不随撤销变化，也不进入导出文件。保存过的项目在关闭页签或软件时自动保存，绝不自动删除；新建且从未保存的项目才询问是否保留。删除已有项目需在首页右键选择并确认。

项目历史上限独立写入 `project_settings`，不属于模型操作历史。旧项目首次打开时从当前状态迁移这个值，此后切换旧状态也不会覆盖它。包含历史与仅当前状态的 `.cbmodel` 导出都会保存当前设置。

历史节点的形状、颜色和名称独立写入 `history_marks`，不会修改模型事务。完整历史归档保留现存标记；仅当前状态导出保留当前节点的标记并映射到新的初始节点。删除或裁剪节点时同步清理标记，恢复时忽略已被删除节点的残留标记。

## 开启与恢复

打开已保存的项目时，程序根据项目 UUID 与历史记录比对同路径工作副本。相符或处在同一历史链上的落后副本可重用；内容分歧时询问另开或替换工作副本，不会无提示地覆盖来源。

若恢复提示项目状态文件损坏且找不到上一个完成状态，表示 `current_state` 和 `current_state.previous` 都不足以提供可靠恢复点；不代表已保存的 `.cbmodel` 或 `.bbmodel` 必然损坏。请先备份完整工作目录，再尝试正常打开已保存的工程。不要只删除单个交易、元素或贴图文件，因为它们可能仍被操作索引引用。重复点「恢复」不能保证找回未保存内容。

同一工作项目只允许一个程序窗口写入。撤销／重做只沿实际使用的历史分支导航；若某一步快照缺失或损坏，会停在该边界并保留当前模型，而不是用不完整数据覆盖现状。

历史上限按全局序号从早到晚清理单笔记录，不因父记录被清理而删除较新的子分支。`history_pruned` 原子记录已删除的序号，避免中断清理后旧文件重新出现。断开分支的根使用 `history_roots/` 索引贴图恢复基准，实际数据在 `history_textures/` 按内容去重；只为保留的根维护基准，不为每个操作保存完整贴图。后续记录继续使用双向差异，跨根切换仍校验结果。过期基准与无引用内容随清理回收；包含历史的导出会保留这些索引。

项目记录在独立工作线程中处理，减少保存、历史读取和归档对窗口输入的占用。最近历史可从内存恢复，几何撤销尽量只刷新受影响部分；涉及贴图时保持已有画面，等待恢复资源就绪后再替换。后台执行仍遵循操作顺序与完整性校验，不改变现有工作目录或 `.cbmodel` 格式。

打开超过半秒显示进度窗。大型历史归档先还原当前元素与贴图，其余不可变历史在后台读取，窗口底部显示细进度条。期间的撤销可读取尚待写入的记录。临时的 `.history-import.cbmodel` 与 `.history-import` 用于中断恢复，完成后自动清理；它们不是额外历史快照，也不会进入再次导出的归档。
