# 动画开发前的第一轮优化

[English](OPTIMIZATION_2026-11-06.en.md) · [架构概述](../ARCHITECTURE.md) · [原始审查](PRE_ANIMATION_AUDIT_2026-11-05.md)

本轮落实透明排序、组拖动预览、修改器求值、最近模型撤销、图层缓存生命周期和导出读回优化。下表来自生成模型与临时用户目录；耗时是本机样本，不是所有设备上的速度保证。

## 实现边界

### 渲染与组拖动

`render/ordered-face-mesh.js` 保持透明面的顶点缓冲，只更新绘制顺序的索引。支持 16／32 位索引；设备不支持大索引时保留原有路径。深度排序复用临时条目，几何失效时清除旧面的引用。

`editor/rigid-transform-preview.js` 判断普通组能否使用现有 GPU 矩阵预览。拖动期间不改项目几何，松手只提交一次。Java／基岩方块的约束、几何修改器及需要全局面排序的透明组仍使用求值路径，避免预览改变限制或遮挡。此实现尚不是多组动画姿态系统。

### 修改器

一次求值内，共用同一组修改器的元素复用组合变换。`model/cube-overlap-index.js` 先按尺寸正负及边界分桶，候选重合时才比较完整的无序顶点。严格的带符号轴置换可直接变换边界；一般旋转仍检查八个角点。

预览、Cube 烘焙和组烘焙共用索引；正负形仍被区分，边界相同但顶点不同也不会误删。同时修正元素拷贝修改器在选择变换后的失效判断。

### 撤销

`project/recent-model-history.js` 缓存最近的完整项目状态，覆盖模型、UV、Shape、修改器、绘画、图层及贴图属性，不再遇到非元素操作就清空。新建和重新打开项目都会建立当前状态缓存；一次磁盘撤销后也会补上相邻重做状态。

磁盘操作继续按队列执行并核对目标，但近期状态的显示不等待该队列。缓存最多保留 9 个状态（8 步），共享未改变的节点、图层和 PNG 字符串，按 64MiB 估算内存预算裁剪，并遵守项目历史上限。PNG 比较在工作线程中使用保留透明像素原始 RGB 的无损解码，避免重新编码产生假操作；后台解码失败或尚未转换的 Blob URL 则退回磁盘校验。超出窗口、历史树跳转或清理仍采用校验路径；新建分支时保守重建窗口，避免预览已清理的父节点。可编辑对象不持有缓存的可变数组。

独立临时实例中人为暂停后台提交，1000 Cube 的本地撤销约 80ms、重做约 26ms，图层撤销约 60ms、重做约 24ms。恢复后台后核对了实际模型和图层状态。这些时间包含界面更新，来自本机单次样本；它们不代表所有模型都能在这个时间内恢复。

后续编辑会排在已预览的撤销之后写入正确分支。校验或写入失败时保留可见工作并停止后续写入。保存、关闭仍等待必要记录落盘。本轮没有放宽原子写入或恢复规则，也没有使大量初始文件的落盘本身变快。

纯像素／图层撤销保留现有模型和网格；图像解码使用有界的不可变源缓存，绘画前复制为可编辑画布。后端命中完整贴图状态时不再重放差异。历史达到上限后的清理只删除失去引用的已知快照，不再逐个访问全部保留快照或递归扫描元素目录；新记录同时索引删除用的快照。历史父节点异常会报错退出，避免循环等待。

### 贴图与资源

`common/utils/layer-raster-regions.js` 为复杂叠色缓存 64×64 来源块，RGBA 缓存全局上限 8MiB。落笔只失效相交块；替换来源使用新缓存键。删除图层／贴图和关闭项目会释放所属数据，关闭最后一个相关项目清空块缓存。项目关闭后，尚未结束的图像解码不会重新填回缓存，后续图层解码也会停止。

保留 Canvas 原有的混合和透明像素舍入路径。曾测得更快的 CPU 合成方案，但它会让部分低透明度像素产生 1 级色值差异，因此未采用。

`texture/export-bake.js` 每个输出帧独立复用来源像素。读回预算由原例的 720MiB 降到 4MiB，不跨帧复用可能已经改变的画布，也不更改编辑器图层或播放状态。

## 验证与后续工作

- 源码及模块图检查；模型、格式、修改器、渲染、绘画选区、图层、模块和日志测试。
- 日志测试涵盖分支、故障恢复、贴图双向差异，以及预览后立即编辑、存储失败和目标不一致。
- 隐藏窗口逐像素对照：全部叠色模式、组与蒙版、局部缓存更新；正交／透视、负尺寸、镜像、面区分和选择预览。输出一致，WebGL 无错误。
- 真实应用验证最近撤销后的新分支确实保存正确；导出验证序列帧、平铺、高像素箱型 UV 和剔除面。

仍需继续处理：100 层复杂叠色依然可能超过一帧预算；最近撤销尚未达到原审查的 33ms 目标；修改器几何变化和透明组拖动仍可能重算。进入动画前还需独立姿态求值与多组矩阵提交，使播放不修改文档、不触发历史或封面保存。大型事件控制器的依赖注入也仍需按功能边界逐步缩小。

可复跑脚本：

- `scripts/verify-optimization-rendering.cjs`：对比基线版本的旧合成器和现有合成器；透明绘制与非索引路径对照。
- `scripts/compare-modifier-performance.mjs`：同进程旧、新修改器求值对照。
- `scripts/audit-animation-performance.cjs`：支持 `--render`、`--pixels`、`--suffix=名称`。
- `scripts/audit-workflow-performance.cjs`：真实撤销、分支保存和缓存释放；支持 `--suffix=名称`。
- `scripts/profile-viewport-input.cjs`：真实应用视角测试。
- `scripts/test-optimization-caches.mjs`：缓存上限、失效、快照隔离、索引回退、去重及组拖动提交。

量测原始文件在 Git 忽略的 `build/performance/`，包括 `modifier-comparison-2026-11-06.json`、`camera-1000-2026-11-06.json`、带 `-final` 后缀的性能报告，以及 `optimization-rendering.json`。
